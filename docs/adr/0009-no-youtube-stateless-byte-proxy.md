# No YouTube, and the only server left is a stateless byte proxy

Status: accepted, not yet built.

Dropping YouTube import removes yt-dlp. Moving chunking onto byte ranges ([ADR 0010](0010-byte-range-chunks-asr-placed-cuts.md)) removes ffmpeg. What remains needs no disk, no CPU and no state: follow the redirect a podcast host answers with, add the CORS headers it does not send, and hand a transcription endpoint a byte range dressed up as a whole file. That is a Cloudflare Worker which pipes `upstream.body` straight into its Response, so the bytes never enter the isolate and a 26MB slice costs the same CPU as a 200-byte one. Nothing to deploy but a static page and one Worker.

We considered keeping a small Node server for YouTube alone. Rejected: it drags ffmpeg, yt-dlp, a container and a host back in to serve one source, and it re-opens an abuse surface that is otherwise closed — an endpoint that will run yt-dlp against any URL anyone posts is a free transcoding farm, and [ADR 0008](0008-browser-owns-all-state.md) has just removed the password that used to stand in front of it.

The proxy cannot be deleted along with the server, and the reason is not YouTube. Three things a browser cannot do for itself, all observed on real feeds: one podcast host answers browser requests with no CORS headers at all; another answers a 302 that the transcription endpoint refuses to follow, failing with `media_fetch_failed`; and a third splices advertising by User-Agent, answering `curl` with 43,421,257 bytes and a browser with 44,263,131 — a 30-second difference in the same episode. That last one is why every byte must go through the proxy rather than only the awkward ones: a byte offset means nothing across two versions of a file, so one client with one fixed User-Agent has to fetch all of them.

Known ceiling: the proxy is open by construction. Anything a third-party transcription endpoint must fetch cannot be authenticated by a secret, because the only place to keep that secret is a static page that hands it to everyone. A content-type allowlist stops it being a general web proxy, an origin allowlist stops other websites from calling it (the browser enforces that one, not us), and a shared key in the query string buys a rotation lever rather than protection. Rate limiting is the actual backstop, and it belongs in Cloudflare's own rules, not in this code.
